# Extraction and evaluation

Default provider: mock-v2, a deterministic parser for labelled fictional quotations. It parses actual selectable PDF text, not fixture-name lookups. It is not live AI. Supported scalar labels are Supplier, Quotation reference, Quotation date (or Date), Currency, Subtotal, Tax and Grand total, ignoring label case and extra label whitespace. Item rows may use Item: description | quantity | unit price | line total, or a contiguous Item: description block followed by Quantity, Unit Price and Line Total labels. Each Item starts a new block; unrelated text closes it. Orphan item fields are ignored. Missing, repeated or conflicting fields remain null with unavailable evidence. Dates and decimal values are not guessed, normalized or calculated by extraction. Human review is mandatory.

The optional live provider uses OpenAI Responses structured outputs and server-side Zod validation. Configure EXTRACTION_PROVIDER=live, OPENAI_API_KEY and an explicit supported OPENAI_MODEL. It sends only bounded page text/page numbers, no stored credentials, session tokens or arbitrary tools. store=false is requested. Documents are untrusted data, never instructions to approve, change roles or choose destinations. Provider calls have a deadline and input/output limits. No live credentials were requested for the free local core; no live extraction is claimed verified.

## Versioned datasets
The preserved fixtures/expected-v1.json defines the initial eight fictional PDFs: clean, missing reference, arithmetic inconsistency, multi-page, ambiguous supplier, image-only/scanned stand-in, instruction-injection text, and high value. Expected values are explicitly specified from the source labels and checked arithmetic. This is a small authored exercise, not a diverse benchmark or independent annotation study. The scanned fixture is a graphic-only PDF, not a real supplier scan. Additional malformed PDF and unsupported text exercise rejection.

Dataset v2 (scripts/fixtures.ts and fixtures/expected-v2.json) preserves those source cases and adds labelled-fields.pdf, reproducing title-case labels, Date and separately labelled item fields. It contains nine cases. The regression values are explicitly authored, not generated from parser output.

Run npm run fixtures, then npm run evaluate. The evaluation invokes the real PDF text parser, provider and validator. It compares only the explicitly enumerated expected fields and expected validation outcome. Full clean case includes line items. Coverage is not full-field accuracy over arbitrary PDFs. Rejected scanned input is recorded as the expected unsupported outcome.

## Executed mock results
See evaluation-results.json for the run timestamp and per-case evidence. Latest executed: 24 selected field checks, 24 correct; nine validation/rejection outcomes, nine correct. These figures apply only to mock-v2 on authored dataset v2. The initial v1 result was 16/16 selected fields and 8/8 outcomes. No live-provider accuracy, performance, confidence calibration or adversarial security guarantee follows from them.

Evidence snippets are accepted only when an exact excerpt exists on the stated parsed page. Missing or invalid evidence is marked unavailable; source evidence is still not a calibrated probability and must be checked by a human. No missing value is silently invented or replaced with a guessed exchange rate.
